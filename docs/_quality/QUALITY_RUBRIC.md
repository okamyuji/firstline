# 文書品質ルーブリック

レビュー役はこの観点で`docs/`の文書を確認します。表記はdoclintが機械で検証するので、レビュー役は表記を確認しません。

## 重大度

| 重大度 | 定義 |
|---|---|
| Critical | このまま実装すると、二重販売、購入確定の消失、払ったのに席がない状態、認証の欠陥、サービスの停止のいずれかが起こります |
| High | 文書どうしが矛盾しているか、決定事項に対応する設計が欠けています |
| Medium | 実装者が判断に迷い、利用者に聞き返す必要があります |
| Low | 読みにくさだけの問題です |

## 文書ごとの必須の節

| 文書 | 必須の節 |
|---|---|
| requirements/scope-and-decisions.md | 目的、題材、決定事項、ADR、設計書で決めること |
| design/basic-design.md | 決定表、決定事項との対応表、構成、接続設定、グループコミット、起動と停止、在庫、決済、状態遷移、認証、画面、文字列の言語、メール、観測、設定とCLI、配備、品質ゲート |
| design/adr/ADR-*.md | 状況、決定、理由、結果 |

## 観点

1. 決定の追跡 `scope-and-decisions.md`の決定事項と「設計書で決めること」のそれぞれに、基本設計書の対応する設計があること。
2. ADRの一致 同じ決定を扱うADRと基本設計書の記述が、同じ結論になっていること。
3. 状態遷移の網羅 保留、購入、期限切れ、払い戻しの各状態に入る遷移と出る遷移があり、期限切れ後の決済完了が払い戻しに至ること。
4. 永続性 購入確定の応答がfsyncの完了より前に返る経路がないこと。
5. 移行可能性 SQLite、PostgreSQL、MySQLの3実装で同じ振る舞いになることを、testcontainersのテストで確かめられる設計になっていること。
6. 検証可能性 規模拡大の判断基準が、実際に測れる値で書かれていること。

## 技術的妥当性の特別区分

次の指摘はレビュー役1名だけのものでも採用します。ルーブリックに対応する観点があるかどうかは問いません。

- データの消失
- セキュリティの欠陥
- サービス停止の危険
- 範囲外の機能の混入
- 文書どうしの決定的な矛盾
- 契約と実装の不一致
